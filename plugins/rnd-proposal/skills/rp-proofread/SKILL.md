# 외부 모델 교정 스킬

## 0. 이 스킬의 원칙 — 받되, 그대로 넣지 않는다

외부 모델은 **문장을 좋게 만들라**는 지시를 받으면 수치와 출처를 지운다.
`COP 2.5` 를 「높은 성능계수」로, `Energies 18(14) 3806(2025년)` 을 「선행 연구」로
바꾸는 것을 개선이라 여긴다. **그건 이 문서에서 즉시 감점 사유다.**

> **교정은 제안까지만 받는다. 반영은 검사를 통과한 것만 한다.**

이 프로젝트에서 한 번 겪었다 — em-dash 를 줄이라는 지시 하나가
슬롯 구분자까지 바꿔 골격 게이트가 슬롯 64개를 전부 위반으로 잡았다.

## 2. 교정 요청 프롬프트 — 고정 블록

**금지 목록을 먼저 준다.** 뒤에 붙이면 모델이 이미 고친 뒤다.

```
아래는 한국 정부 R&D 연구계획서의 일부입니다. 문장만 다듬어 주세요.

[반드시 지킬 것]
- 숫자·단위·연도·출처 표기를 한 글자도 바꾸거나 지우지 마세요
- 문장 끝은 개조식(~함 / ~임)을 유지하세요
- 목록의 들여쓰기 층위를 바꾸지 마세요 (- 와   - 의 구분)
- em-dash(—)를 쓰지 마세요. 구분자는 콜론(:)입니다
- 날짜는 연도까지만 씁니다 (2035년 O / 2035-12-31 X)
- 표(| ... |)의 행·열 개수를 바꾸지 마세요

[고쳐도 되는 것]
- 어색한 조사·어순, 중복 표현, 지나치게 긴 문장

[출력 형식]
고친 곳만 아래 형식으로 나열하세요. 전문을 다시 쓰지 마세요.
  원문: <그대로>
  수정: <고친 것>
  이유: <한 줄>

--- 본문 ---
<여기에 장 내용>
```

**전문 재작성을 금지하는 이유** — 전문을 받으면 무엇이 바뀌었는지 사람이 못 본다.
제안 목록으로 받아야 채택·기각을 고를 수 있다.

## 3. Chrome MCP 절차

```
1) tabs_context_mcp             ← 먼저 현재 탭을 본다
2) navigate  https://gemini.google.com/app
3) 모델을 3.1 Pro 로 바꾼다      ← Flash 는 전문을 거부한다
4) Set-Clipboard 로 프롬프트 적재
5) computer 로 입력창 클릭 → ctrl+v → 전송 버튼 클릭   ← JS 로는 안 된다
6) 응답 대기 (Pro 는 추론 시간이 길다. 3~5분)
7) 응답 구간만 잘라서 수거
```

응답이 길면 `get_page_text` 는 프롬프트 반향까지 전부 돌려줘 낭비다.
`원문:` 위치를 찾아 **그 구간만** 잘라 온다.

```javascript
const t = document.body.innerText;
[...t.matchAll(/원문:/g)].map(m => m.index);   // 위치를 먼저 본다
```

### 입력·전송 — ★ JS 로는 안 된다 (실측)

**클립보드 붙여넣기 + 실제 클릭**이라야 한다.

```powershell
Set-Clipboard -Value (Get-Content <프롬프트파일> -Raw -Encoding UTF8)
```

그 다음 `computer` 도구로 **실제 클릭·키 입력**을 한다.

```
① computer left_click  → 입력창 (화면을 먼저 찍어 좌표를 잡는다)
② computer key ctrl+v
③ javascript_tool 로 입력 길이와 전송 버튼 좌표를 읽는다
④ computer left_click  → 전송 버튼 좌표
```

> ★ **왜 JS 가 안 되나 (2026-09-09 실측).**
> `document.execCommand('insertText')` 는 DOM 에는 글자를 넣지만
> **프레임워크 상태가 그걸 모른다.** 화면에는 빈 입력창이 그대로 보이고
> 전송 버튼을 눌러도 아무 일도 안 일어난다.
> 합성 `PointerEvent`·`MouseEvent` 도 마찬가지다(`isTrusted` 검사로 보인다).
> **세 번 막히고 실제 클릭으로 뚫렸다.**
>
> JS 는 **읽기용으로만** 쓴다 — 입력 길이 확인, 전송 버튼 좌표 계산, 응답 대기.

> 전송 버튼은 `aria-label="메시지 보내기"` 다. **`보내기` 로 부분 매칭하면
> `공유 및 내보내기` 가 먼저 잡힌다** — 누르면 안 되는 버튼이다.

### ★ 좌표로 클릭하지 마라 — `ref` 를 쓴다 (2026-09-09 실측)

도구 프레임과 페이지 뷰포트의 **좌표계가 다르다.**

    도구 프레임   933 x 564
    뷰포트       1153 x 697      ← 0.809배

`getBoundingClientRect()` 로 얻은 좌표를 그대로 클릭하면 **엉뚱한 곳을 눌러
`document.activeElement` 가 BODY 가 된다.** 붙여넣기가 조용히 무시된다.

**해법은 좌표를 안 쓰는 것이다.**

```
find("Gemini prompt input textbox")  →  ref_NNN
computer left_click  ref=ref_NNN     →  activeElement 가 입력창이 된다
computer key ctrl+v
find("send message button")          →  ref_MMM
computer left_click  ref=ref_MMM
```

**클릭한 뒤에는 반드시 확인한다.**

```javascript
document.activeElement === document.querySelector('div[contenteditable="true"]')
```

`false` 면 클릭이 빗나간 것이다. 다시 좌표를 계산하지 말고 `ref` 로 가라.

> 이것 때문에 오늘 세 번 막혔다. 「Chrome 창이 포그라운드가 아니라서」라고
> 잘못 진단했는데, `document.hasFocus()` 는 내내 `true` 였다.

### 모델을 Pro 로 바꾼다

입력창 오른쪽 모델 선택기(`모드 선택 도구 열기`)를 눌러 **3.1 Pro** 를 고른다.
기본값 Flash 는 전문 길이를 거부한다.

### A/B 실험이 뜰 때

Gemini 가 **「어떤 대답이 더 유용한가요? 옵션 A / 옵션 B」**를 띄우는 경우가 있다.
선택 버튼이 접근성 트리에 없으므로 **양쪽 내용을 모두 읽어 기록**하고 넘어간다.
두 벌을 비교할 수 있어 오히려 유용하다.

### 막힐 때

셀렉터가 안 맞거나 응답을 못 읽으면 **2~3회 시도 후 멈추고 사용자에게 보고한다.**
같은 동작을 반복하지 마라. 화면을 직접 복사해 붙여 주시는 편이 빠를 때가 많다.

## 5. ★ 반영 전 검사 — 이게 이 스킬의 핵심

채택분을 `30_proposal.md` 에 반영한 뒤, **조립하기 전에** 돌린다.

```bash
python "$CLAUDE_PLUGIN_ROOT/scripts/check_proofread.py" \
    --before <원본 build.md 사본> --after <교정 반영 build.md>
```

보는 것:

| 검사 | 판정 |
|---|---|
| **수치 소멸** (원본에 있던 값이 통째로 사라짐) | **FAIL** |
| **출처 소멸** (특허번호·저널·과제번호) | **FAIL** |
| 수치 횟수 감소 | 보고만 — 중복 정리는 정당하다 |
| 리드·슬롯 개수 변동 | **FAIL** (골격 게이트가 뒤에서 또 잡는다) |
| em-dash / 연월일 표기 | **FAIL** |

`exit 2` 면 **채택하지 않는다.**
