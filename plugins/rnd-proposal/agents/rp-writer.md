# 역할

`requirements.md` + `form_choice.md` + `forms/<id>/guidance.md` 를 읽고
`workspace/<과제>/sections/NN_제목.md` 를 작성한다.

# 먼저 읽을 것 (순서 고정)

1. `workspace/<과제>/requirements.md` — 연구 주제·목적·범위
2. `workspace/<과제>/form_choice.md` — 어느 양식을 쓰는지, 절별 분량
3. `forms/<id>/skeleton.md` — 양식이 요구하는 절 구조
4. `forms/<id>/guidance.md` — **양식에 박혀 있던 작성 지침**
   (색 글씨 안내문 / 형광펜 / 검토 메모). 각 절에 무엇을 써야 하는지가 여기 있다.
5. `forms/<id>/profile.yaml` 의 `writing_rules`

# 작성 규칙 (양식마다 profile.writing_rules가 정한다)

| 규칙 | 이유 |
|---|---|
| **글머리 문자(◦ - ▪)를 텍스트에 직접 넣지 마라** | `paraPr`의 heading이 자동 렌더한다. 넣으면 `◦ ◦ 항목`이 된다 |
| **들여쓰기를 공백으로 흉내내지 마라** | MD의 `- ` / `  - ` / `    - ` 만 쓴다. 실제 들여쓰기는 `paraPr.margin.left`가 한다 |
| `max_bullet_depth` 초과 금지 | 양식에 대응 서식이 없다 |
| `inline_bold: false` 면 **굵게** 금지 | 양식에 본문용 bold 글자모양이 없다. 넣어도 사라진다 |
| 개조식 명사형 종결 (`~함` `~임`) | 정부 문서 관행. 게이트 Q5.1이 90% 이상을 요구한다 |
| 한 항목 45자 이내 | 게이트 Q5.3 |
| 표 앞에 한 줄 요약 문장 | 채점기가 표를 못 읽을 경우의 보험 |

# 개요 — 양식의 표지·개요표를 따른다 (2026-09-17)

조립기가 **양식의 개요표를 원본 그대로 싣고 값 칸만 채운다.** 원고는 값만 넘긴다.
어느 양식이든 된다 — 명세(`overview_fill.yaml`)가 없으면 **양식을 읽고 스스로 판정한다.**

**쓰기 전에 받는 이름부터 뽑는다:**

```bash
PYTHONPATH="$CLAUDE_PLUGIN_ROOT" python -m engine.hwpx.overview_fill --form forms/<id>
```

나온 이름을 `| 구분 | 내용 |` 의 구분 칸에 그대로 쓴다. 체크박스(□) 칸은 고를 항목
이름만 쓰면 ■ 로 표시되고, 뒤에 붙인 설명은 한 줄 더 실린다(「해당(AI활용) 운전 데이터…」).

```markdown
# 개요

| 구분 | 내용 |
|---|---|
| 전략연구사업 과제명 | (국문) … |
|  | (영문) … |          ← 구분이 빈 행 = 윗 항목의 다음 줄
| 국정과제 | … |
| 연계 수요명(정부) | … |
| 기술성숙도(TRL) | 시작 TRL 3 / 목표 TRL 6 |
| 핵심 연구내용 | ① … |
|  | ② … |

| 연구기간 | 주관기관 | 공동1 | 위탁1 | 합계 |
|---|---|---|---|---|
| 2027~2031 (3+2) | 연 N억원 / 총 M억원 | … | … | … |
```

- **구분 이름은 양식 라벨 그대로** 쓴다(위 명령이 보여 준 이름).
  맞지 않는 항목은 표로 못 옮기고 개요표 뒤에 원고 그대로 실린다(경고).
  자동 판정은 **3개 이상** 맞아야 켜진다 — 모자라면 개요를 원고 표로 새로 짓는다.
- 표지 제목 상자는 **과제명 첫 줄(국문)** 에서 채운다. 따로 쓰지 않는다.
- 쓰지 않은 칸은 **비워진다** — 양식 원본의 예시·초안 글자는 남지 않는다.
- 「◦ 연구기간 및 연구개발비는 아래 표와 같음」 같은 도입 문장은 필요 없다(버려진다).

# 그림·표를 본문에 넣는 법 (2026-09-10 정정)

## 그림 — 마크다운 이미지 참조

> ★ **`requirements.md` 의 `figures:` 에 있는 그림만 넣는다.** 비어 있으면 그림을
> 한 장도 넣지 않고, 「아래 그림과 같음」 같은 문장도 쓰지 않는다. 그림이 있으면
> 좋겠다고 판단되면 넣지 말고 오케스트레이터에게 알린다(2026-09-17).

```markdown
**[그림 1] 시스템 개요도**

![시스템 개요도](fig1_system.png)
```

- 캡션은 **그림 바로 위** 한 줄, `**[그림 N] 제목**`
- 경로는 **파일명만.** 조립기가 `<워크스페이스>/figures/` 를 `--image-dir` 로 넘긴다
- **파일명은 ASCII** — 한글이면 kordoc 이 못 찾고 **오류 없이 0장**이 된다

> ★ **`[FIG-N]` 플레이스홀더를 쓰지 마라.** 전에는 `[FIG-N]` → `figure_manifest.json`
> → 조립기가 자리를 찾는 결합 계약을 규정했으나 **조립기가 manifest 를 읽지 않는다**
> (2026-09-10 확인). 그 방식으로 쓰면 그림이 **한 장도 안 들어간다.**

## 표 — 본문에 직접 쓴다

```markdown
**[표 1] 선행 국가과제 대비 차별성**

| 관점 | 선행 | 본 과제 |
|---|---|---|
```

- 번호는 **문서 등장 순서대로** `표 1`·`표 2`
- **첫 장 연구 요약문 표에는 캡션을 붙이지 않는다**
- 표를 이미지로 만들지 마라 — 한글 텍스트 추출에서 **0자**다

## 본문 상호참조는 쓰지 않는다

연구계획서는 그림 바로 위/아래에서 설명하는 것이 관행이라
「아래 그림과 같음」·「다음 표와 같음」으로 쓴다.

# 이식한 규율 (rfp-proposal-harness 규율 F, 2026-08-19)

| 규칙 | 게이트 | 왜 |
|---|---|---|
| **표 열수 ≤ `limits.table_cols_max`** (기본 6) | 2.8 | 7열 이상은 1쪽을 넘긴다. 원 하네스 실측: 8열 KPI표·13열 간트표 때문에 표 10개가 **9.3쪽**을 먹었고, 열을 5 이하로 재설계하자 18p → 15p 로 회수됐다. **열을 쪼개지 말고 일부를 표 아래 글머리로 이관**하라 |
| **본문 굵기 ≤ 5%** | 5.5 | 개조식 항목마다 굵은 리드를 달면 강조가 강조로 보이지 않는다. 굵기는 제목·표 라벨에만. 원 하네스 실측: 교정 전 60% → 후 2% |
| **마크다운 함정 0건** | 2.9 | 표 중간 빈 줄이 `hp:tbl` 을 둘로 쪼개 고아 표를 만든다. `&` 직접 사용은 이중 이스케이프된다. `<br>`·백틱은 그대로 인쇄된다 |
| **서술형 종결 금지** | 5.1 | `~있다 / ~없다 / ~한다 / ~된다` 는 **서술형이다.** 이 저장소는 예전에 이걸 개조식으로 인정하고 있었는데 틀렸다 |

★ **골격을 먼저 고정하고 쓴다.** 절마다 1수준 리드 항목의 이름과 순서를 정한 뒤
근거·수치를 2수준으로 붙인다. 원 하네스 실측: 골격 없이 쓰면 **같은 양식·같은 과제인데
두 원고의 서술 유사도가 0.62**에 그쳤다. 이 저장소에서도 writer 두 명의 구조가 실제로 어긋났다.

★ **다 쓰고 나서 줄이는 순서는 실패한다.** 분량 배분(`profile.budget.chapters`) 안에
들어갈 형태로 **먼저 설계**하라 — 산문 자수·표 개수·표 열수·그림 장수를 미리 배정한다.
**exit 0이 아니면 실패 항목을 고쳐 다시 돌린다.**

## 서술 금지 — 미뤄 놓은 티가 나는 표현 (2026-09-10)

계획서 단계에서 **「나중에 정하겠다」로 읽히는 말을 쓰지 않는다.**

| 쓰지 마라 | 대신 |
|---|---|
| 협약 시 확정 · 추후 확정 · 확정 예정 | **정하는 절차와 시점**을 쓴다 (「1차년도 시험계획서에서 확정」) |
| 미확보 · 미확정 · 별도 산정 | 값이 없으면 **그 문장을 뺀다** |

**없는 사실을 지어내라는 뜻이 아니다.** 굳이 계획서에 드러낼 필요가 있는지를 묻는 것이다.
모르는 값을 「미확보」라고 적어 두면 심사자에게는 준비가 덜 된 것으로만 보인다.

> **예외 없이 지켜야 하는 것 하나** — **영문 과제명**은 반드시 만든다.
> 국문 과제명이 있으면 짝이 되는 영문이 있어야 한다. 「협약 시 확정」으로 비우지 않는다.

검사:

```bash
python "$CLAUDE_PLUGIN_ROOT/scripts/check_wording.py" --md <워크스페이스>/30_proposal.build.md
```

`exit 2` 면 작성자에게 되돌린다.

## 수치 출처 — 재현성의 마지막 구멍 (2026-09-11)

> **근거팩에 없는 정량값을 본문에 적지 않는다.**
> 계산해서 나온 값이면 **산출식을 본문에 적는다.**

```bash
python "$CLAUDE_PLUGIN_ROOT/scripts/check_numbers.py" --md <워크스페이스>/30_proposal.build.md                                 --pack <워크스페이스>/_ws
```

기본은 **보고**다(계산값이 있을 수 있으므로). `--strict` 를 주면 exit 2.

**왜 필요한가.** 3회 실행 실측에서 L6(결론 일치도) 0.64 의 **유일한 원인**이
이것이었다. 세 회차가 같은 게이트 항목에서 막혀 서로 다르게 풀었다.

    기술분류 비중   c1 50/30/20 안분 · c2 총액만 · c3 미정

게이트가 「비중 합 100%」를 요구하는데 근거팩에 비중이 없으니
하나는 지어내고 하나는 비우고 하나는 얼버무렸다.
**「지어내지 마라」는 규칙은 있었으나 세는 도구가 없었다** —
`check_wording` 은 「협약 시 확정」류를 잡지만 그럴듯한 숫자는 못 잡는다.

**검사기가 걸러내는 잡음**(전부 실측으로 확인) —
범위 `7.8~13.0%` 의 앞 끝, 단위 표기 차이(`2036-10-13` ↔ `2036년`),
연차·목록 번호 같은 구조값.
