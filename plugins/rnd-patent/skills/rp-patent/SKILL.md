# 특허 조사 스킬

## 0. 이 스킬이 필요한 이유 — 실측 결함

R1 평가에서 근거정합성 위원이 **−3.5점**을 매겼다.

> 「특허번호는 회피설계의 유일한 근거인데 **익명**이다」

근거팩 `24_patent.md` 에 `EP 3362739 B1`·`EP 2959236 B1`·`KR 10-1895383` 이 있었는데
**본문에는 특허번호가 0회**였다(「특허」 5회 · 「회피」 2회 · 번호 0회 · 「청구범위」 0회).
**조사를 하고도 본문에 실체가 안 남으면 조사를 안 한 것과 같다.**

## 1. 조사 실행

`rfp-proposal-harness:researcher` 를 **특허 축**으로 호출한다.

```
Agent(subagent_type="rfp-proposal-harness:researcher",
      prompt="축: 특허. 주제: <연구주제>. 출처가 붙은 근거 파일을 만든다.")
```

산출물은 `<워크스페이스>/_ws/24_patent.md` 형태로 둔다.

## 2. 조사 결과가 갖춰야 하는 것

| 항목 | 왜 |
|---|---|
| **특허번호 전체** (`EP 3362739 B1` 꼴) | 이게 없으면 본문이 익명 인용이 된다 |
| **권리자** | 회피 대상이 누구인지 |
| **만료일 / 존속 상태** | 만료됐으면 회피가 불필요하다 |
| **청구범위 요지** | 회피축을 세우려면 무엇을 피하는지 특정돼야 한다 |
| **KR 패밀리 유무** | 국내 출원이 없으면 국내 실시에 제약이 없다 |

## 3. 본문에 쓸 때 — 단서를 강제한다

특허번호를 본문에 올릴 때 **KR 패밀리 확인 여부**를 함께 적는다.
확인하지 않았으면 「**KR 패밀리 확인 후 확정**」을 붙인다.
붙이지 않으면 다음 평가에서 「미확인 주장」으로 새 감점이 된다.

**회피축을 단일로 세우지 마라.** R1 기술성 위원 지적(−2.5):
회피축이 「열원 60~90℃」 하나였는데 **캐스케이드 고단 입구 130~140℃ 는 청구범위 안**이었다.
운전 구간이 여럿이면 **구간마다** 회피 논리가 필요하다.

## 4. 하지 말 것

- **근거팩에 없는 특허번호를 쓰지 마라.** 번호는 지어내면 즉시 들통난다
- 만료 여부를 추정하지 마라 — 확인되지 않으면 「존속 상태 미확인」으로 적는다
- 조사 후 **근거팩을 동결**한다. 이후 작성 단계는 팩만 읽고 새 검색을 하지 않는다
  (재현성 실측: 동결이 L6 결론 일치도를 **0.64 → 0.83** 으로 올렸다)
